# 漸進プロセスモデル(MIDI生成モデル `process`)

LYRAの三つ目のMIDI生成モデル(2026-09-26、Claudeの提案で追加)。「鳴らす」「MIDIにする」のポップアップで選ぶ。

- 実装: `js/process.js`(展開のエンジン。Geminiを使わない)、`js/midi.js`(「漸進プロセスモデル」の節。生成の流れ・プロンプト・カード・作り直し)
- ほかのモデル: 基本の楽典モデル(`models/gakuten.md`)、見立て蔵モデル(`models/mitategura.md`)

---

## 1. 考え方: 時間を「過程」として扱う

3つのモデルは、時間の扱い方が違う。

| モデル | 時間の扱い | 音楽を形づくるもの |
|---|---|---|
| 基本の楽典 | **物語**(起承転結・序破急) | 和声・旋律の目的地・区間ごとの伴奏の切り替え |
| 見立て蔵 | **空間**(要素の身振りの重なり) | モチーフごとの身振りの型と現れ方 |
| 漸進プロセス | **過程**(規則による少しずつの変化) | 短い細胞と、それに掛ける規則 |

短い音の細胞(3〜12音)に規則を1つ掛けると、音楽が規則に従ってひとりでに少しずつ変わっていく。
ミニマル音楽(ライヒのフェイズ、グラスの加算)、ペルトのティンティナブリ、中世のイソリズム、カノン、
イギリスの転調鳴鐘(チェンジ・リンギング)など、**「規則を決めたら、あとは規則が音楽を運ぶ」**書法に共通する考え方。

このモデルを選ぶ理由:

- **Liteモデルに向く**: Geminiが書くのは短い細胞と規則の選び方・パラメータだけ。長い旋律や拍の通し番号を数えさせないので崩れにくい
- **独自性の心配が小さい**: 細胞が短く、聞こえてくる形の大半は規則が作るので、既存曲の旋律に似るおそれが小さい(反芻は無し、Geminiは1回)
- **時間の長さに強い**: 規則は何小節でも続けられるので、16〜64小節の長い下地も作れる(既定16小節)
- **Max 9との相性**: 規則はそのままMaxのパッチ(カウンター・リスト操作)に移せる考え方で、LYRAで作った規則をMaxで発展させやすい

## 2. データモデル

Geminiが1回の出力で書くもの(`PROCESS_SCHEMA`):

```json
{
  "name": "mall_phase.mid",
  "description": "どこがこの入力らしいか(40字)",
  "concept": "コンセプト(60字)",
  "commentary": "規則が時間をどう変えていくか・Cubaseで層ごとの音色を選ぶヒント(200字)",
  "tempo": 116,
  "layers": [
    {
      "name": "反響",
      "process": "phase",
      "register": "mid",
      "why": "なぜこの規則か(主役60字、ほか30字)",
      "notes": [{ "note": "E4", "duration": 0.5 }],
      "step": 0.25, "shift_every": 4,
      "repeats": 2,
      "talea": [0.75, 0.25, -0.5, 1],
      "voices": 3, "delay": 2, "transpose": [0, -5, -12], "speeds": [1, 1, 2],
      "triad": "Am", "position": "alternate",
      "hold": 8
    }
  ]
}
```

| フィールド | 役割 |
|---|---|
| `layers` | 層(最大3)。先頭が主役。層ごとに規則は1つ |
| `process` | 規則の語彙(3節)。**語彙にない値は、その層だけ鳴らさない**(見立て蔵と同じく安全側に無視) |
| `register` | low(中心 C3)/ mid(中心 D4)/ high(中心 E5)。アプリが細胞をオクターブ単位で動かして平均を中心に寄せる |
| `notes` | 細胞。音名+オクターブと音価(拍)。規則によって使い方が違う(3節) |
| そのほか | 規則ごとのパラメータ(使わない規則では無視) |

## 3. 規則の語彙(7種)

| 規則 | 表示名 | 何が起きるか | 使う項目 | 向いている入力 |
|---|---|---|---|---|
| `phase` | フェイズ | 同じ細胞を2声で繰り返し、2声目だけが `shift_every` 回ごとに1音ずつ先へずれる。一巡すると再びそろう | notes(8〜12音、等分の刻み)、step(1音の拍)、shift_every | 揺らめく模様・うなり・水面・反響 |
| `additive` | 加算・減算 | 1音目 → 1〜2音目 → … と1音ずつ伸ばし、全部そろったら1音ずつ縮める。各段を `repeats` 回 | notes(4〜8音、音価つき)、repeats | 成長・堆積・呼吸・開花 |
| `isorhythm` | イソリズム | 音高の並び(カラー)とリズムの並び(タレア)を別の長さで循環させる。組み合わせが少しずつずれ、一巡するまで同じ形が戻らない | notes(カラー)、talea(拍。負の値は休み) | 回る歯車・季節の巡り・織物 |
| `canon` | カノン | 同じ旋律を2〜4声が `delay` 拍ずつ遅れて追いかける。声ごとに移調と速さ(音価の倍率)を変えられる(メンスーラ・カノン) | notes(旋律)、voices、delay、transpose、speeds | 反響・群れ・こだま・追いかけっこ |
| `tintinnabuli` | ティンティナブリ | 順次進行の旋律(M声部)に、主和音の音だけを弾く鐘の声部(T声部)を1音ずつ添える | notes(M声部)、triad、position | 祈り・静けさ・鐘・透明な光 |
| `change_ringing` | 転調鳴鐘 | 4〜6個の鐘を、隣り合う2つを入れ替える規則(プレーンハント)で順番を変えながら鳴らす。2×鐘の数の列で元の順(ラウンズ)に戻る | notes(鐘の音)、step | 教会の鐘・祭り・機械仕掛け・数の模様 |
| `drone` | ドローン | 細胞の最初の音と5度上を保ち、`hold` 拍ごとに打ち直す。ほかの層の地 | notes(1音)、hold | 地・空調・持続する気配 |

## 4. 展開の手順(`js/process.js`)

共通:
- 長さは `小節数 × 4拍`(4/4のみ)。すべての規則は曲の終わりまで繰り返し、終わりで切る
- 細胞は `register` に合わせてオクターブ単位で動かす(平均が中心に最も近くなる移動量)
- 音の長さに 0.9 のゲートを掛ける(同じ高さの連打が .mid で途切れないように)
- 強弱: 細胞の頭(各繰り返しの1音目)を強め(約84)、ほかは約70。シード付きの乱数で ±4 のわずかな揺れ
- 層の声部ごとにパート `g1`〜`g6`(合計6声部まで)。パートの名前は層の名前(2声以上ある規則は「反響1」「反響2」)
- マーカー: 主役の層の規則の節目(ずれの段・加算の段・一巡・声部の入り・ラウンズに戻る所)

規則ごと:

- **phase**: 細胞を `step` 拍の等分で鳴らす。k 回目の繰り返しで、2声目は細胞を `floor(k / shift_every) mod 細胞の長さ` 音だけ回転させた並びを鳴らす(音の位置はそろえたまま、並びだけがずれる=離散化したフェイズ)
- **additive**: 段の並び `1, 2, …, n, n−1, …, 1` を曲の終わりまで繰り返す。各段は細胞の先頭から `段の音数` 個を、細胞の音価どおりに `repeats` 回
- **isorhythm**: i 番目の音 = カラー[i mod カラーの長さ]、音価 = タレア[i mod タレアの長さ](負の値は休みで、カラーを進めない)。**カラーとタレアが同じ長さだと、ただの繰り返しになるので、タレアを1つ縮める**。タレアが無ければ細胞の音価を使う
- **canon**: 声部 v は `v × delay` 拍から入り、旋律を `speeds[v]` 倍の音価で、`transpose[v]` 半音移して繰り返す
- **tintinnabuli**: 主和音(`Am` `C` `F#m` など。読めなければ旋律の最初の音を根音にした短三和音)。T声部は旋律の各音から見て、above=すぐ上/below=すぐ下/alternate=上下交互の、最も近い主和音の音(同じ音は飛ばす)。音価は旋律と同じ
- **change_ringing**: 鐘の番号の列(ラウンズ 1234…)を1打 `step` 拍で鳴らし、列ごとに、奇数回目は (1,2)(3,4)…、偶数回目は (2,3)(4,5)… の組を入れ替える(プレーンハント)。各打の長さは step×1.6(響きを残す)
- **drone**: 細胞の最初の音と5度上を、`hold` 拍ごとに打ち直す(強さ 58 / 50)

## 5. 入口とGeminiへの指示

- 入口: 課題カード・画像カードの「鳴らす」、発言の「MIDIにする」 → モデルを選ぶポップアップ → 漸進プロセスモデル
- 生成前に聞くこと: 長さ(小節数、既定16)、主役の規則(おまかせ/フェイズ/加算・減算/イソリズム/カノン/ティンティナブリ/転調鳴鐘)、
  イメージ元の光景・言葉(つないだ気づき・課題・画像の印象が初期値)、追加の注文
- 渡すもの: 画像(画像カード。印象が空なら同じ出力で印象を書かせてカードに残す)、つないだカード、ソウルの知識(アーティスト名・曲名の項目は外す)
- 指示の要点:
  - 入力の気分・動き・質感に最も合う規則を選ぶ(揺らめく水面→phase、成長→additive、巡る季節→isorhythm、こだま→canon、祈り→tintinnabuli、鐘→change_ringing)
  - 層は1〜3。主役を1つ決め、必要なら地(drone など)を足す。層が多すぎると規則が聞き取れない
  - 細胞は短く素朴でよい(主役は規則)。層どうしで調・旋法をそろえる
  - 細胞は既存の曲の旋律・リフ・動機を引用・模倣しない(規則の考え方は作曲家の技法として自由に使ってよい)

## 6. 出力

```
card.midi = {
  kind: 'process', model: 'process', tempo, beatsPerBar: 4, meters,
  notes: [{ part: 'g1'…'g6', pitch, start, duration, velocity }],
  partNames: { g1: '反響1', g2: '反響2', g3: '空調' },
  markers: [{ beat, label: 'フェイズ: 1音ずれ' }],
  process: { layers: [...](細胞は音番号), bars, seed }
}
```

- 書き出しはLYRAの共通の形: 「1トラックで」/「パート別」(層の声部の名前のトラック)/声部1つずつ
- 作り直し(`reviseProcess()`): 前回の層と規則(細胞は音名に戻す)・コメント・主役の規則の指定・つないだカードを渡してGeminiを1回。
  改善版(`_v2.mid`…)を右隣に線でつないで置く
- 試聴の音色は既定でビブラフォン(マレット系はミニマル音楽の刻みが聞き取りやすいため)

## 7. 既知の限界

- フェイズは離散化(並びの回転)なので、ライヒの実演のような連続的な加速の途中(ずれかけの揺らぎ)は無い
- 4/4 のみ。規則の周期(例: 12音の細胞)が小節と合わないのは意図どおり(ずれて聞こえるのがミニマルの味)
- 層どうしの和声の衝突はアプリでは調整しない(Geminiに同じ調・旋法にそろえさせているだけ)
- 実機のGeminiでは未確認
