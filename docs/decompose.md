# 解体パイプラインとパラメータレシピ

CLAUDE.md から移した機能別の経緯と決まり(2026-10-03 に分割)。その機能を触る時に読む。絶対条件・開発方針は CLAUDE.md。

- **解体パイプライン**: 構造把握(モジュール名+パラメータ名だけ)→モジュールごと(20件ずつ)の詳細抽出
  →共通語彙の変換表、の順。呼び出しの間は4.5秒空ける(無料枠のRPM対策)。途中で止まったら
  `source.pending`に進み具合が残り「続きから解体」で再開できる。PDFはGemini Files APIへ1回上げて
  URIを使い回し、Files APIがブラウザから使えなかった時だけ18MBまでのインライン送信に切り替える
  (**Files APIのブラウザからの動作は実機未確認**。失敗時は`?debug`のログに理由が出る)
- **PDFはページ単位で切り分けて渡す(2026-09-25、実機計測を受けて変更)**: Serum2の日本語マニュアル
  (36.6MB)は、全体を渡すと1回で入力約19.6万トークン・約88秒かかった(構造把握の実測)。モジュール23個
  ぶん毎回全体を渡すと30分以上かかるため、構造把握だけ全体(Files API、アップロード4.4秒で成功)を渡し、
  各モジュールの「PDF上の通しページ番号」(pdfStart/pdfEnd)も出させる。詳細抽出はそのページだけを
  pdf-lib(jsdelivr、必要な時だけ読み込む)で切り出した小さなPDFを渡す。ページ番号が欠けたモジュールは、
  他のモジュールの「印刷されたページ番号との差」の中央値で補う。切り出したページで目当てのパラメータが
  3割未満しか見つからなければ、前後8ページ広げて1回だけ読み直す
- **Geminiの一時的な失敗は自動で待って再試行**: 503(「high demand」、実機で発生)・500は20/40/60秒待って
  3回まで、429(1分あたり)は65秒待って1回。1日あたりの429はそのまま止める(続きから再開できる)。
  `askGemini()`の例外には`status`(と429なら`perDay`)が付く。`?debug`のログに各呼び出しの秒数・
  入力/出力トークン数・終了理由が出る
- **Geminiの出力の暴走対策**(2026-09-25、Aesthetics Wikiの記事の解体で「Expected ',' or '}' ... position 8306
  (line 13 column 8105)」で停止): 1行が8000字を超えていたことから、Liteモデルが同じ語句を繰り返し続けて出力上限で
  切れたとみている(終了理由は未確認)。`askGemini()`はJSONモードで終了理由がMAX_TOKENSならその旨のエラーにし、
  `askGeminiJson()`は出力が切れた・JSONが壊れていた時に1回だけ自動でやり直す。構造把握は1モジュール40項目まで、
  固有名詞の長い列挙は1項目にまとめるよう**プロンプトで**指示している。
  **responseSchemaに`maxItems`を付けると、このモデルでは400(INVALID_ARGUMENT)で拒否された**(実機で確認)。
  スキーマに型・properties・required以外の制約を足す時は、必ず実機で1回通してから使う
- 著作権ゲート: Web記事の本文は解体にだけ使い保存しない。抽出した説明は160字・140字で切り詰める。
  出典・テキストに書き出し機能は無い。書き出せるのはアプリが生成したMIDI(.mid)・WAV・パラメータレシピだけ
- **モジュールは「UI上の場所」(`module.location`、例: "FXタブ")を持つ**(2026-09-25追加)。Serum2の解体で
  「UTILITYがどこにあるか分かりにくい(FXタブの中)」という指摘を受けた。構造把握で一緒に出させ、左のタブは
  場所ごとに小見出しでまとめ、表示は`modulePath()`で「FXタブ › UTILITY」にそろえる(パンくず・詳細・レシピ・
  アンサンブルに渡す知識)。それ以前に解体したソウルは、資料パネルの「資料から整理する」でPDFを1回読ませて付ける。
  Files APIに上げたPDFのURIは`source.geminiFile`に残し、期限(48時間)内は使い回す
- **パラメータレシピ**(2026-09-25拡張): 発言に付くレシピは「音色づくりに関わる主要な設定を5〜12個」。
  レシピパネルの「初期状態から作る詳しいレシピにする」で、レシピ専用にGeminiを1回呼び、Initから画面の上から順に
  15〜30項目の手順を作る(`card.recipeFull`)。表示は手順の順番を崩さないよう、同じモジュールが続く間だけまとめる。
  「小窓で出す」はChrome/EdgeのDocument Picture-in-Picture(他のアプリより常に手前の小窓)でCubaseの上に浮かべる。
  **クリックなどの実際のユーザー操作からしか開けない**(自動テストで合成したクリックでは開かなかった)。対応して
  いないブラウザでは普通の別ウィンドウ。各行のチェックは`card.recipeDone`に保存
- **レシピの限界と保留(2026-09-25)**: 詳しいレシピで「Serum2のMultisampleを使う」と出ても、どのサンプル・
  ファクトリープリセットかまでは出ない。渡している知識が解体したパラメータ(マニュアル由来)だけで、同梱素材の一覧や
  プリセットの作り込み(複雑なモジュレーションの配線など)はマニュアルに無いため。名前を出させるとLiteモデルは
  実在しない名前をでっち上げやすい。**ファクトリープリセット級の複雑な音作りは、ユーザー判断で保留**。再開する時の
  候補: (1) Max 9の`vst~`でSerum2を読み込み、プリセットの全パラメータ値を読み出して解体する/レシピを流し込む
  (モジュレーションの配線やサンプル選択がホストから見えるパラメータとして出ているかは未確認)、(2) `.SerumPreset`
  ファイルの解析(形式は非公開)、(3) 手持ちの素材名の一覧をソウルに登録してレシピで選ばせる。画面を直接操作させる
  方法は無料運用の外なので対象外
