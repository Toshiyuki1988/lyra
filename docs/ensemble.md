# アンサンブル・ソウル画面・共通の操作

CLAUDE.md から移した機能別の経緯と決まり(2026-10-03 に分割)。その機能を触る時に読む。絶対条件・開発方針は CLAUDE.md。

- **アンサンブルでは、招集されたソウルの全パラメータを「手持ちの知識」として渡す**(モジュールごとにまとめ、
  つないだカードのものは詳しく、他は効果80字・意図40字)。以前は先頭40件に切っていたため、Serum2(229件)では
  後ろのモジュールが見えなかった(2026-09-25修正)。共通語彙の変換表を作る時も全件を見る
- アンサンブルの招集は「線でつながったカードのまとまり」単位。ホームの舞台は毎回「場(STAGE)」として参加し、
  汎用ペルソナ「楽典」も毎回参加する
- **「アンサンブルを聴く」「コード+旋律で鳴らす」は課題カードの編集ガイドのヘックス**(2026-09-25)。カードの上の外側に
  「聴く」「鳴らす」を並べ、その課題カードを含むまとまりが対象になる(Edit=左、Delete=右、ASTR=下、聴く・鳴らす=上)。
  以前は右下の「招集中」パネルのボタンで、最後にタップ/移動したカードのまとまりが対象だったが、どのカードを中心に
  行われるか分かりにくいというユーザー判断でパネルごと廃止した。最後にタップ/移動したカードのまとまりには今も枠の
  印が付く(`renderMembers()`)
- **アンサンブルのカードは傾けない**(2026-09-25)。モックアップどおり±2度傾けていたが、ユーザー判断で真っ直ぐに。
  古いデータの`card.tilt`は残っているが使わない
- **感想とまとめ(2026-09-25、ユーザー要望「気付きからGeminiAIに感想を聞けるように。ゆくゆくは作曲家AIも参加できるように。
  ConstellationのCrews機能に近い」「サマリー機能もだね」)**: js/screens/ensemble.js。
  - **感想**: 気づきカードの上の「感想」ヘックス → 話し手を選ぶ(`showChoiceDialog`)→ Geminiを1回 → 感想カード(`type: 'comment'`、
    120字程度)を右隣に置き、**線を自動で結ぶ**(MIDIの改善版に続く2つ目の例外。何への感想かを辿れるように。`connection.auto`)。
    渡すのは気づきの文と、線で直接つながったカードの要約だけ(ソウルの知識は渡さない=トークン節約)
  - **まとめ**: 下の道具バーの「まとめ」→ 範囲(最後にタップしたまとまり/この舞台全体)・話し手・問い(任意)→ Geminiを1回 →
    まとめカード(`type: 'summary'`、見出し+200〜400字)。線は結ばない。発言カードは声をつなげて渡し、効いた/効かなかったも含める。
    CONSTELLATIONのサマリーと同じく、**問いがある時は全体の総括を前置きに書かせない**(前置きが8割になった実例があるため、
    「最初の一文から答えを書く」まで指示する)
  - **話し手は`voices()`**: 今は「Gemini」(素。文体の指定なし)と「楽典」(アンサンブルと同じ汎用の音楽理論の専門家)。
    **作曲家AIを参加させる時は`voices()`に足す**(例: 作曲家のソウルから、そのソウルの知識と語り口で話す話し手を作る)。
    話し手が1人なら選ぶダイアログは出さない。CONSTELLATIONと同じく、話し手を登録・保存する時にGeminiは呼ばない方針にする
  - 感想・まとめのカードは編集なし(ASTRとDeleteのみ)。ASTRでつなぐと、アンサンブル・鳴らす・作り直しに文として渡る
- **矩形選択と一括移動(2026-09-25、ユーザー要望「ConstellationのFlight Engineerの機能を簡単に使えるように。Shift+ドラッグで
  矩形選択、Shift+矩形範囲タップ&ドラッグで内のカードを一括移動」)**: `js/marquee.js`。モードは持たずShiftだけで使う。
  Shift+背景ドラッグで囲んだカード(一部でも重なれば)を選び、点線の枠(`contentEl`の中なのでズームに追従)で囲む。
  Shift+枠の中(カードの上でもよい)からのドラッグでまとめて動かし、指を離した時に`onCardMoved`・位置の保存・線の引き直し。
  **viewportの捕獲フェーズのpointerdownで受けてstopPropagationする**ので、カードの長押し(編集ガイド)とinteract.jsのパンより先に
  取れる(パンは`lockPan()`でも止める)。Esc・Shiftなしで背景を押す・画面の切り替えで解除。Shiftの無いスマホでは使えない。
  自動テストのブラウザ操作ツールの合成ドラッグ/クリックはページに届かないことがあったので、確認は合成PointerEventで行った
- **矩形選択からの一括削除(2026-09-27、ユーザー要望「Shift+dragの複数カード選択の選択範囲出現時に『選択カードを全削除』『★３以下のMIDIを全削除』の
  ボタンを表示。削除時は２段階警告アラート」→ 同日「★３は残そうか。★２以下が削除対象ね」)**: 選択中はキャンバスの上に固定のバー(ズームで大きさが変わらないよう枠の中には置かない)。
  確認は`showChoiceDialog()`の2回(内訳→「次へ」、元に戻せない念押し→「n枚を削除する」)。削除の中身は画面ごとに違うので、画面が
  `deleteCards(cards)`(と任意で`deletableCard(card)`)を持つ時だけ出す: アンサンブル(画像は端末内の画像も、チャットは覚え書きも消す)と
  ソウル画面(パラメータ・チャット。モジュールのハブは数えない)。**入口画面(ソウルそのもの)には出さない**。「★2以下」は★1〜2と、
  **★を付けていないMIDIも含める**(当初は「★3以下・未評価を除く」。ユーザー判断で未評価を含め、★3は残すように変えた)。Driveのファイル(オーディオ・スクショ)は消さない決まりどおり、カードの参照を外すだけ
- **削除履歴(2026-09-27、ユーザー要望「削除履歴を１０件だけ残すようにして戻せるようにして」)**: `js/trash.js`。矩形選択からの一括削除
  1回を1件として、カードと、消えたカードにつながっていた線の写しを`state.trash`(Driveに保存、新しい順で最大10件)に残す。ヘッダーの
  削除履歴ボタン(設定の左)で一覧を開き、「戻す」で元の画面(アンサンブルの舞台/ソウルのページ)へカードと線を戻してその画面を開く。
  場所は画面の`trashPlace()`が返す。ソウル画面は、戻す時にそのページ(モジュール)が消えていればそのカードは戻せない。
  画像カードの端末内の画像は、一括削除の時点では消さず、履歴から押し出された時に消す。**1枚ずつの削除(編集ガイドのDelete)は対象外**
- **ダイアログは画面の高さに収めて中をスクロール**(2026-09-25、MIDIを作るダイアログが縦に長く「作る」が見切れた指摘)。
  `.modal`に`max-height`+`overflow-y: auto`、`.modal-actions`は`position: sticky`で下に貼り付けて常に見えるようにした
- **画像カード(2026-09-26、ユーザー要望「画像カードを新設し、画像の印象からMIDIを生成できるように」)**: アンサンブルの
  道具バーの「画像」・ドロップ・Ctrl+Vで置く(`type: 'image'`、js/screens/ensemble.js)。**観賞用ではなく「試しては入れ替え」を
  繰り返すための材料**(ユーザー判断。Pixabayの軽い画像をドラッグ&ドロップで入れる想定)なので:
  - **画像はDriveに上げない**。この端末のIndexedDB(`lyra-images`、キーはカードID。js/app.js の`putLocalImage()`など)に
    長辺512px・JPEG品質0.72で置く。Driveに上げると、Driveのファイルを消さない決まりのため入れ替えるたびに増え続ける。
    Driveのデータに残るのは名前・印象の文・試した履歴だけ。別の端末では「この端末に画像がありません」と出て、ドロップで入れ直せる。
    カードを削除するとIndexedDBの画像も消す(端末内の一時置き場なのでDriveの削除禁止の対象外)
  - **入れ替え**: 画像カードへのドロップ/左下の「入替」ヘックス/パネルのボタン/そのカードを選んだままCtrl+V。位置・線はそのまま、
    印象は空に戻し、前の画像の名前と印象を`card.tried`(最大20件)に残す
  - 上の「鳴らす」(コード+旋律)・「ビート」で、画像をそのまま`files`でGeminiに添付する。課題カードの「鳴らす」「ビート」も、
    まとまりに画像カードがあれば添付する(画像があればソウルが無くても「鳴らす」を使える)。1回に最大3枚。
    印象の文(Editで書ける)が空の画像は、**同じ1回の出力の`impressions`**に視覚の言葉のまま印象を書かせてカードに残す
    (呼び出し回数は増やさない)。実機のGeminiで、画像の印象がMIDIに出ること・印象がカードに書き込まれることをユーザーが確認済み(2026-09-26)
  - **画像検索(Pixabay API、`js/imagesearch.js`、2026-09-26、ユーザー判断)**: 道具バーの「画像」と、画像カードの「入替」で
    キャンバスを隠さない浮いたパネルが開く。**開いたままサムネイルを次々クリックすると、同じカードの画像がその場で入れ替わる**
    (最初のクリックでカードが無ければ置き、以後はそのカード)。「PCのファイルから」も同じパネルにある。キーは設定画面の任意欄で
    `lyra.pixabayApiKey`(localStorage)。取り込むのは`webformatURL`(640px)で、端末内に512pxで置く。カードの表示に
    PixabayのURLは使わない(規約: ホットリンクしない)。`card.source`に出どころ(pageURL・user)を残し、パネルからPixabayへ飛べる。
    規約どおり、検索結果に「画像: Pixabay」を出し、同じ検索は24時間キャッシュする(localStorageに直近10件。同じオリジンの
    CONSTELLATIONと容量を共有するため小さく)。APIも画像のCDNも`Access-Control-Allow-Origin: *`(curlで確認)。
    本物のAPIキーでの検索・取り込みは公開URLでユーザーが動作を確認済み(2026-09-26)。取得手順はREADME.md手順9
- **プラグインの専門AIチャット(2026-09-27、ユーザー要望「プラグインごとに専門AIチャットを作って。Constellationの座談会カードの
  形式を参照して、トピックごとにカードで独立。ボトムツールから追加したらプラグインソウルの現在開いている階層に置く」)**: `js/soulchat.js`。
  - ソウル画面の下の道具バー「チャット」(**プラグインのソウルだけ**)→ トピック(+任意で最初の質問。書けば置いてすぐ聞く)→ 今開いている
    モジュールのページにチャットカードを置く。データは`soul.chats[]`(`moduleId`付き)で、ソウル画面のscopeの派生配列に
    `[module, ...params, ...chats]`として載る(削除時は`soul.chats`側も外す。モジュール削除でそのページのチャットも消える)
  - 置き場所は、そのページのカードとスクショの右隣(画面の真ん中だと未配置のパラメータの列を隠した)。置いた後にそこへ視点を寄せて光らせる
  - カードは座談会の形(見出し・会話ログ・入力欄。Enterで送信、Shift+Enterで改行、IME変換中のEnterは送らない)。話し手は
    「〇〇の専門AI」1人。**1回の送信でGeminiを1回**(送信するまでは呼ばない)。返事は結果がそろった瞬間に「シュコッ」
    (`playChatReplySound()`、CONSTELLATIONと同じ音)。失敗したら質問を会話から外して入力欄へ戻す
  - 渡す知識は`window.LyraSoulMaterial`(アンサンブルと同じ形)。**カードのあるページのパラメータと、ASTRでチャットにつないだ
    パラメータを詳しく**、他は短く。会話は後ろから6000字まで。知識に無いことは「(推測)」、無い名前を作らない、資料を長く引用しない
  - 答えで触れたパラメータを`params`で出させ、実在するものだけチップにする(押すと同じページならその場で選び、別のページなら移る)
  - 会話ログの上ではカードの移動・パン・ズームより文字の選択とスクロールを優先する(`js/canvas.js`の`.chat-log`の除外、ホイールは
    ログのスクロール)。カードは見出しをつかんで動かす。入力途中の文はDriveに残さない。著作権ゲートどおり書き出し機能は無い
  - **チャットカードに`overflow: hidden`を付けない**: 初版で付けていたため、カードの外に出る編集ガイドのヘックス(Delete など)と
    トンボが切り取られ、削除できなかった(ユーザー指摘)。角は見出し・入力欄で丸める。会話ログの上でも、動かさずに0.45秒押せば
    編集ガイドが出る(`attachLogLongPress()`。ログはスクロール・文字選択を優先しているため、カード本体の長押しが届かない)
  - **アンサンブルへの拡張(同日、ユーザー要望「アンサンブル画面でもカードからチャットを展開できるように。アステリズムで繋いだ、
    別プラグインのAIがチャットに参加できるように」)**: プラグインのソウルカード・パラメータカードの上の「チャット」ヘックスで、そのカードの
    右隣にチャット(`type: 'chat'`, `soulId`=主)を開き、線を自動で結ぶ。チャットカードにASTRで**直接**つないだ**別のプラグイン**の
    ソウルカード・パラメータカードの持ち主のAIが参加者に加わる(見出しに並ぶ。プラグイン以外の区分は加えない)。つないだパラメータカードは
    詳しく、気づき・課題・MIDIなどは要約を文脈として渡す。**参加者が何人でも1回の送信でGeminiは1回**(`voices`に全員ぶん書かせ、
    表示だけ1人ずつ間を置いて出す。主は必ず最初に答え、他は加えることがある時だけ話す)。アンサンブルのまとめ・MIDI生成などには
    `describe()`(トピック+直近のやり取り)で渡る。ソウル画面のチャットは今もそのソウルのAIだけ
  - **実機のGeminiでは未確認**(テストはヘッドレスEdge+CDPでGeminiを模擬して、作成・送信・履歴・失敗・チップ・削除・
    編集ガイドの表示・アンサンブルでの展開と複数AIの参加を確認)
- **アンサンブル画面でShift+A**: 全ソウル(今の舞台を除く)の一覧を区分ごとに出し、クリックしたソウルのカードを置く
  (対象のカードがあればその右隣)。線は自動で結ばない(Asterismは手動接続のみ)。入力欄にフォーカスがある時と、
  ダイアログを表示中は反応しない
