## 要望の原文
見立て蔵の続きをやる。デイリー機能などでGeminiAPIに作らせた「語彙」だが、「神秘」型が、ほとんど９割「ブゥーーーーン　パァアアアーン」といった低音に途中から高音が重なるデチューン三層構造でワンパターンだった。最初に君に作らせた数種類のようなバリエーションがない。GeminiAPIへの指示文を改良してほしい。また、それぞれの語彙のモチーフなどはいいので、MIDIを再生成する機能が欲しい。構想を聞かせて。

(構想への答え)１作り直したら★と確認済みは戻して。２　不要　３　これは見本なので作り直しボタンをグレーアウトか何かで押せないようにしておいて。　４デイリーについては後で不具合を伝えるので保留。

## 目的・背景

## 対象範囲(後半)
1. 窓(js/mitategura.js)のカードに「音を作り直す」ボタン
   - Gemini で足した語彙(`entry.generated`)だけ押せる。手書きの語彙(SEED・js/mitatecolor.js の文様・鳥)にもボタンは出すが、`disabled` でグレーアウトし、title に「見本なので作り直せません」
2. 押すと `showFormDialog()` で「ひとこと注文(任意。例: 高い音域だけで)」を聞く。Gemini の回数(1回)と今日の残りを書く。`dataLoaded` が false なら使えない
3. js/mitategen.js に `regenerateRequest(rec, note)` と `regenerate(rec, opts)` を足す
   - 渡すもの: その型の rules・AVOID・名前・moment・turn・season・senses(変えない)、今の音のデータ(「これと違う形に」)、注文
   - 神秘型: 身振りを1つ割り当てる。今の `data.gesture` と同じものと、今の形が「持続に遅れて高音」(`shapeOf().lowHigh`)なら clear を避ける。音域も割り当てる
   - 和文様型・鳥型: 今の音と違う組み立てに、だけを書く(身振りの割り当ては無い)
   - 出力の形はその型の schema から name・moment・turn・season・senses を除いたもの(device と音のデータ)。整えるのは既存の `sanitize()`
   - 反芻はしない(使う回数を1回にする。ユーザーが耳で選ぶ)
4. 聴き比べ: 結果を「前の音」「新しい音」の2つの再生ボタンで聴けるダイアログ。決めるのはラベル付きの2択「新しい音にする」「前の音のまま」(`showChoiceDialog()` か同等。背景タップ=前の音のまま)
5. 「新しい音にする」→ 帳の記録の `data` の device と音のデータ(神秘: parts・gesture/文様: figures・holds・beat・b・len/鳥: events・beat・b・len)を差し替え、`regenAt`(ISO日時)を足す。
   `hydrated` のキャッシュをその id だけ消す。★と確認済みを消す(`state.prefs.mitate.ratings[id]` を消すか `{}` に)。帳のファイルを保存する(既存の自動保存の印)

## 受け入れ条件
- [ ] 生成した語彙に「音を作り直す」があり、押すと注文の欄→Gemini 1回→聴き比べ→2択の流れになる
- [ ] 手書きの語彙のボタンはグレーアウトで押せない(押しても何も起きない・Gemini を呼ばない)
- [ ] 「新しい音にする」で、名前・一言・切り替わり方・季節・感覚は変わらず、音と device だけが変わる。窓の再生・⇩ MIDI・LYRA Host への送信が新しい音になる
- [ ] 「新しい音にする」で★と確認済みが消え、未確認(点線)に戻る。「前の音のまま」では何も変わらない(★も)

- [ ] 形が壊れた出力(sanitize がエラー)は差し替えず、理由を出す。429・失敗・止めた時も今の音のまま

- [ ] 作り直しの最中に窓を閉じる・もう一度押す時の扱い(二重に呼ばない)
- [ ] 操作の衝突: 窓のカードのクリック(再生・★・✓)と新しいボタンがぶつからない

## 設計・制約
- 【推測】ボタンの文字は「作り直す」、置き場は「外す」の隣
- 【推測】注文の欄は任意。空ならそのまま作る
