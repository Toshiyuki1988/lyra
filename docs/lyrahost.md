# LYRA Host との連携・VST の対応表・プリセット目録・保留中の構想

CLAUDE.md から移した機能別の経緯と決まり(2026-10-03 に分割)。その機能を触る時に読む。絶対条件・開発方針は CLAUDE.md。

## LYRA Host との連携: LYRA 側(2026-10-01、M3 の PROTOCOL.md 版 1 に沿って)

- **形の正本は lyra-host の `PROTOCOL.md`**(クラウドの作業ブランチ `claude/eager-shannon-89fjxd` にある。M1〜M4 済み。Serum2 のパラメータの一覧の実データ
  `docs/serum2-2.1.1-params.json` も。MIDI CC の代わりを除いて541個)
- `js/lyrahost.js`: 接続の部品。クリックの中で `lyrahost://open?session=S&port=47650` を開き(**await より前に。ユーザー操作の中でないと止められる**)、
  `ws://127.0.0.1:47650/` へ0.5秒おきに20秒試し直す → `hello` → `welcome`。`request()`は "id" で返事を対応させる。ホストの「LYRA へ送る」は
  テキストの `result` の**すぐ次のバイナリが WAV** → `onResult` の処理 → `ack`。受け取った音はこの端末の IndexedDB `lyra-hostaudio`(キーはカードの ID)。
  Drive には上げない
- プレミックスの MIDI のカードの「**ホスト**」ヘックス(右下の外側): カードの ID と MIDI を `open` で送る(`preferSaved: true`=同じカードならホストに保存した
  音源・状態を戻す)。**音源はホストに任せる**(ユーザー判断。LYRA からは `plugin` を送らない)
- 「LYRA へ送る」で届いた WAV は、**元のカードの音を差し替える**(ユーザー判断。カードは MIDI を持ったまま、`s.hostAudio` に音源の名前など)。
  カードには「MIDI(VST: 音源名)」と出る。「ⓘ」の「内部音源の音に戻す」か「音色を変えて作り直す」で内部音源の音に戻る(端末の WAV も消す)。
  その端末に WAV が無ければ(別の端末など)内部音源で鳴らす。**ホストで直したノートは、今はカードの MIDI に書き戻さない**(次の段階)
- **MIDI が変わったカードは `preferSaved: false` で開く**(2026-10-01、実機「16小節に伸ばしたのに、ホストには8小節しか渡らなかった」)。
  **原因**: `preferSaved: true` だと、ホストはそのカードの保存した状態(音色**とノート**)を戻し、送った MIDI を使わない(PROTOCOL.md の決まりどおり)。
  伸ばす前にホストで開いていたので、伸ばす前の8小節が戻っていた。**直し方**: ホストへ最後に送った MIDI の指紋を `s.hostMidiKey` に覚え、違えば `preferSaved: false` で
  送った MIDI を開かせる(指紋の無い以前のカードは、伸ばした履歴があれば変わったとみなす)。同時に `restoreSound: true`(保存した音色だけ戻し、ノートは送った MIDI)を送る。
  **LYRA Host が対応済み**(a815a1d の main。返事に `soundRestored`、`capabilities` に `"restoreSound"`)。対応していないホストでは、音色はホストで今読み込んでいるまま
- **LYRA Host で新しく作った音を持ち込む**(2026-10-01、ユーザー要望「LYRA Host で簡単な MIDI を書いて、プラグインの音を LYRA に持ち込む」):
  プレミックスの道具バーの「**ホスト**」で LYRA Host を起動して(起動済みなら前面に)つなぐ。ホストで MIDI を書いて「LYRA へ送る」を押すと、LYRA の知らないカードの ID
  (ホストが付ける `host-…`)で届くので、**開いているプレミックスのアクティブなエリアに新しいカード**(`midiInline` の `model: 'lyrahost'` + `hostAudio`)として置く
  (`adoptFromHost()`/`placeFromHost()`)。カードの ID はホストの ID のままなので、ホストでもう一度送ると同じカードの音が差し替わり、「ホスト」で開けば保存した状態が戻る。
  プレミックスを開いていない時は、音は IndexedDB、中身は localStorage の `lyra.hostPending` に預かり、プレミックスを開いた時に置く(**案内の画面では置かない**。
  最初は案内の画面の空の入れ物に置いて消していた)。「このMIDIについて」の使用モデルは「LYRA Host で作った音」。
  確認: 偽のホストのメッセージで、入口画面で届く → 預かる → プレミックスを開くと置かれる、開いている時はすぐ置かれる、同じ ID の再送は差し替え、を確かめた。
  LYRA につながっていない時にホストが書き出すファイル(`ドキュメント\LyraHost\LYRAへ送る\`)の読み込みは未実装
- 実機で最初の関門になりそうなこと(PROTOCOL.md 7 節): Chrome の「ローカル ネットワークへのアクセス」の許可(初回に「許可」)と、
  ホストの「ファイル → LYRA 連携 → lyrahost:// を Windows に登録する」。つながらない時の逃げ道(ホストが `ドキュメント\LyraHost\LYRAへ送る\` に
  書き出す WAV と JSON を LYRA で読み込む)は未実装
- **LYRA Host を LYRA の上に浮かぶ小窓で出す**(2026-10-01、ユーザー要望「別ウィンドウとのやり取りを抑えたい」。ブラウザにネイティブの画面は埋め込めないので、
  埋め込みではなくウィンドウの操作の工夫で補う=ユーザー判断で案1): LYRA Host に「常に手前・枠の細い・リサイズと移動が自由な小窓のモード」
  「音源の画面をホストのウィンドウの中に収める」「WebSocket の `window` メッセージ(action: float/normal/hide/show、anchor=ブラウザの窓の画面上の位置と拡大率、place)」
  をクラウドへ依頼した(`capabilities` に "window")。LYRA 側は `LyraHost.floatWindow()` を、MIDI のカードの「ホスト」・画像からの音色・記録した音色で開いた直後に呼ぶ
  (ホストが対応していなければ何もしない)。ホストが覚えた位置があれば、ホストがそちらを優先する
  → **LYRA Host が対応した(2026-10-01、コミット efd8465)**。LYRA の `floatWindow()` の形は PROTOCOL.md 4 節のままで、変更は要らなかった。返事は `windowState`
  (位置は CSS px)。`open` に `float: true` を付けても同じ。**ブラウザのページの拡大(Ctrl+ホイール)が 100% でないと位置がずれる**(`devicePixelRatio` だけ変わるため)。
  小窓の中に音源の画面(Serum2 など)も出せる。実機で確かめること: LYRA Host の UNVERIFIED.md 52〜58(拡大率 125%/150%・複数モニター・Serum2 の操作・Space・行き来)
- 確認: ブラウザの中に PROTOCOL.md どおりに振る舞う偽のホストを置いて、起動 → hello → open → result と WAV → カードの音の差し替え → ack →
  内部音源に戻す、を確かめた。**本物のホスト(Windows・公開の LYRA)でも連携に成功した**(2026-10-01、ユーザーの実機。Chrome の許可と lyrahost:// の登録の関門も越えた)

- **音の情報(result.sound、2026-10-02)**: ホストが "soundInfo" に対応していれば、「LYRA へ送る」に音源と FX(最大4)の名前・uid・プリセット名(ユーザーが手で書いたもの、null はよくある)・全パラメータ・メモが付く
  (lyra-host の PROTOCOL.md 8 節、docs/LYRA_SIDE_5_SOUND_INFO.md)。全部はこの端末の IndexedDB(`LyraHost.putSound`、数百KBになり得る)、Drive のカードの `s.hostAudio.sound` には要約
  (スロットごとの名前・preset・audible と、changed/automated のパラメータ、1スロット160まで)。語彙は `state.prefs.hostLexicon[uid]`(プリセット名ごとの回数・よく動かすパラメータ。audible:false は数えない)。
  「ⓘ」に「音源: Serum 2(…)→ FX1: …」とメモ・動かしたパラメータ(ソウルの対応表があればソウル側の名前も)。古いホストは今までどおり。確認は Serum2 の実データ(541個)から組んだ模擬の sound で。**本物のホストではまだ**

## ソウルと VST のパラメータの対応表(2026-10-01、`js/hostmap.js`。ソウルの「挟み撃ち」育成の最初の一歩)

- プラグインのソウルの道具バーの「**VST**」: LYRA Host に今読み込んでいる音源のパラメータの一覧(`listParams`。MIDI CC の代わりは除く。Serum2 は541個)を
  もらい、ソウルのパラメータと突き合わせて `soul.hostMap` に保存する(Drive)。音源がソウルと違う時は、確認のダイアログで「やめる」
  - `hostMap = { plugin: { name, vendor, version, uid }, updatedAt, vst: [{ id, name, min, max, steps }], map: { <ソウルのパラメータのid>: { id(VSTのID), by: 'name'|'gemini'|'user', confirmed } } }`
  - **1. 名前で自動**: モジュール名+パラメータ名を語に分け、言い換え(Cutoff ↔ Freq、Resonance ↔ Res、Position ↔ Pos、Unison ↔ Uni など)をそろえて比べる。
    似ている度合い0.75以上で、2番目の候補と0.15以上離れている時だけ結ぶ(Env 1 と Env 2 を取り違えないように)
  - **2. 残りは Gemini に1回だけ**まとめて聞く(ソウルの側は s番号、VSTの側は数字のIDで渡す)。**返ったIDは実在するものとだけ照合し、無いものは捨てる**
    (でっち上げの名前を弾く)。確かさ0.5未満も捨てる。名前から意味の分からないもの(`A Param44`、`FX Main Param 3` など)は自動でも Gemini でも結ばない
  - **3. 結果はすべて未確認**。パラメータの右パネルの「VST(LYRA Host · 音源名)」で、確認済みにする・付け替える(一覧から選ぶ。手で選んだら確認済み)・外す
  - まとめのダイアログで、「ソウルにあってVSTに見つからなかったもの(解体の誤りか非公開)」と「VSTにあってソウルに無いもの(解体の取りこぼし)」を出す
  - 同じ音源で突き合わせ直す時は、確認済み・手で付け替えたものを残す
- 確認: Serum2 の実データ(LYRA Host のクラウドが保存した `docs/serum2-2.1.1-params.json`)で、名前での自動が27個中22個を**すべて正しく**結ぶこと
  (Cutoff → Filter 1 Freq、WT Position → A WT Pos、ENV 2 の Attack → Env 2 Attack など)、偽のホストと模擬の Gemini で全体の流れ、
  実在しないIDが弾かれること、右パネルでの確認済みを確かめた。**本物の Gemini・本物のホストではまだ**
- 実機で突き合わせた結果、**マニュアルに書かれていない VST のパラメータが大量にあった**(ユーザー確認)。「VSTにあってソウルに無いもの」をソウルに足す機能は未実装(候補)
- **レシピを LYRA Host へ送る・今の値を読む**(アンサンブルの発言の「レシピ」のパネル。ソウルに対応表がある行があれば出る):
  - 「**LYRA Host へ送る**」: 対応表で VST のパラメータに読み替え、値を表示の文字列のまま `setParams` で送る。送る前に `getParams` で、結んだ ID の名前が
    対応表とそろっているかを見て、ホストの音源がレシピのソウルと違えば止める。ホストが受け付けなかった行(「やや高め」「LPF」のようなあいまいな値・
    VST に無い名前)は、「Gemini に直してもらって送り直す」で、VST の実際の範囲と選択肢(選択肢はホストの `listParams` の `valueStrings` から。Drive には持たない)を
    見せて Gemini 1回で具体的な値に直し、送り直す。**選択肢に無い値は捨てる**。直して送れた値はレシピにも残す
  - 「**ホストの今の値を読む**」: ホストで耳で詰めた値で、レシピの値を書き換える(変わる行を見せて確認してから)。ホストで直した・詰めた値の行には「VST」の印(`r.fromHost`)
  - レシピのパネルの行は表示用の写しなので、書き戻しは `onChange(index, value)` でカードの本体(`card.recipe[index]`)に書く
  - 確認: 偽のホストで、送る → 断られた2行(LPF・やや高め)を Gemini(模擬)が「MG Low 12」「35 %」に直して送り直す → 3項目が送れる、今の値を読む
    (800 Hz → 1.2 kHz)を確かめた。**本物のホスト・本物の Gemini ではまだ**
- 次の候補: 「VSTにあってソウルに無いもの」をソウルに足す(解体の取りこぼしの補充)/ ホストで詰めた音色の値を、ソウルに「音色の記録」として残し、話し合いの知識に渡す

## 画像から VST の新しい音色(パッチ)を作る(プレミックス、2026-10-01)

ユーザー要望「花の画像から、MIDI ではなく Serum2 の新音色を作る最速動線」。押すのは「画像を選ぶ」「音色(画像カードの右下のヘックス)」「ホストの Ctrl+L」の3回、Gemini 1回。
- 画像カードの「**音色**」→ 音源(LYRA Host との対応表があるプラグインのソウル。前回の選択を覚える `lyra.patchSoul`)と注文を聞く →
  LYRA Host に**音源を名前で読み込ませる**(この動線だけは音源を送る。ユーザー判断。普通の「ホスト」ヘックスは今までどおり音源をホストに任せる)→
  初期状態にする → ホストの `listParams`(選択肢つき)と画像を Gemini に1回渡し、**Init からの設定一式**(15〜40項目)・名前・狙い・役割(pad/pluck/bass/lead/keys/fx)・
  主音を作らせる → **実在する ID・実在する選択肢だけに絞る** → 役割に合わせた**試奏の MIDI をアプリが作って**(Gemini なし。パッドは持続和音、プラックは分散和音など)
  ホストで開き直し、設定を `setParams` で流し込む → プレミックスに音色のカード(画像カードと線でつなぐ。カードの ID はホストに送った cardId と同じ)
- Gemini に渡すパラメータからは、名前から意味の分からないもの(`Param44` など)・**Mod のAmount/Out(配線が見えないので使えない)**・Bank・Bypass などを外す。
  同じ選択肢の並び(Warp の型・フィルターの型)は1回だけ書いて記号で参照する(トークンの節約)
- **初期状態**: LYRA Host に「`open` の `freshPlugin: true`(音源を読み込み直して Init に)」をクラウドへ依頼済み(`capabilities` に `freshPlugin` が載ったら使う)。
  未対応の間は、公開パラメータを全部初期値(`defaultValue`)に戻してから流し込む(**配線・ウェーブテーブル・エフェクトの種類は前の音色のまま残る**と画面に出す)。
  同じく依頼済み: `open` の `params` でも表示の文字列を受け付ける(`paramResults` で結果を返す)
  → **LYRA Host が両方に対応した(2026-10-01、コミット 4d9c71a、CI #12)**。LYRA は `capabilities` を見て自動で `freshPlugin` を使う。
  注意: Init は音源の側が決める(**Serum2 で自分の音色を既定にしていると、それが初期状態になる**)。Serum2 の Init ではフィルターや一部のオシレーターが**オフ**なので、
  プロンプトで「オフのモジュールを使う時は、On/Enable の設定も入れる」と指示している
- カード: `s.patch = { soulId, plugin, name, concept, role, root, settings: [{ id, name, text, why, ok, reason, approximate, fromHost }], imageId, at }`。
  「ⓘ」に設定の一覧と、**ホストの今の値を読む**(詰めた値で設定を書き換え、「VST」の印)・**ソウルの音色の記録に残す**(`soul.patches`。同じ名前は上書き)・
  **記録した音色で開く**(どの MIDI のカードからも。音源を名前で読み込み、初期状態にしてから流し込む)
- 確認: Serum2 の実データと偽のホスト・模擬の Gemini で、全体の流れ(open(初期状態・音源名)→ listParams → 初期値へ → Gemini → 試奏の MIDI で開き直し → 流し込み)、
  実在しない ID と選択肢に無い値が弾かれること、画像の添付、ⓘの3つのボタンを確かめた。**本物のホスト・本物の Gemini ではまだ**
- テストの注意: ブラウザ操作ツールで、長く待つスクリプトが**2回実行される**ことがあった(ホストへの送信・カード・ダイアログが2つずつになる)。
  2回目を止める印(`if (window.__ranN) … else { window.__ranN = true; … }`)を入れて確かめると、アプリは1回ずつ動いていた

## プリセット目録(2026-10-01、`js/presetcat.js`)

ユーザーの気づき「Serum2 には潤沢なプリセットがある(花の開花のような音もあった)。しかしそれを一発で取り出せる把握構造が LYRA にない」。
**音色の自動生成(画像から新しい音色を作る)は、ユーザー判断で当面保留**(Init からだと単純な音になる。複雑さの大部分はウェーブテーブル・配線・エフェクトの種類で、
公開パラメータからは触れないため)。代わりに、既にあるプリセットを意味で引ける目録を作った。
- **Serum2 のプリセットのファイルの形(このPCで調べた)**: 置き場所は Serum2 の設定(`%APPDATA%\Xfer\Serum 2\Serum2Prefs.json` の「Serum Presets Path」)。
  ユーザーの PC では `D:\ドキュメント\Xfer\Serum 2 Presets\`(`Presets\Factory\<カテゴリ>`・パックごとのフォルダ)。`.SerumPreset` が830個(うち35個は Mac の「._」付属ファイル)・
  Serum1 の `.fxp` が1313個。`.SerumPreset` の先頭は「XferJson」+ 0x00 + ヘッダーの長さ(uint32、9バイト目)+ 4バイト + JSON(17バイト目から。presetName・presetAuthor・
  presetDescription・tags・product・version)。**本体はその後ろの zstd で圧縮されたデータ(`28 b5 2f fd`)で、中身も JSON の見込み**(未確認。読めれば、ウェーブテーブル・配線・
  エフェクトまで含めた構造が取れ、保留にした「プリセットマスター」への道になる)。`System\presets.db`(SQLite)はプリセットのデータベース(タグ・評価・メモ)
- **説明(presetDescription)の実態**: 795個中、空206・URLだけ42・文章547。文章も短い一言で作者ごとにばらばら(弾き方のヒント「MW = Filter Cutoff」、音の性格「Textured sine pad」、
  着想「Nils Frahm type」、遊び)。**タグは13種類の技術的な分類だけ**(Wavetable・Poly・Mono・Multisample・Granular・Spectral・Arp など。音の印象のタグは無い)。
  公式の「音色一つずつの解説の一覧」は無いと見ている。意味が分かるのは「名前(頭の記号がカテゴリ、PL=プラックなど)+カテゴリのフォルダ+説明」
- **目録**: プラグインのソウルの道具バーの「**目録**」→ プリセットのフォルダを1回選ぶ(`Serum 2 Presets` を選べば中の `Presets` から読む)→ 各ファイルの先頭だけを読んで
  「名前・パック・カテゴリ・説明・作者・タグ」を集める(Gemini なし)。**目録はこの端末の IndexedDB `lyra-presets`**(2000件ほどで大きい。プリセットのファイルも端末にしか無い)。
  Drive のソウルには件数と日時だけ(`soul.presetCatalog`)。Serum1 の `.fxp` は名前とフォルダだけ
- **探す**: 目録の窓で言葉の絞り込み(Gemini なし)/「Geminiに探してもらう」(言葉)/ プレミックスの画像カードの「**プリセット**」ヘックス(下の真ん中。画像)。

## 保留: Cubase(VST)との連携(2026-09-29、ユーザー判断で保留。懸念の整理だけ)

**A. プレミックスをCubase版(VSTプラグイン)にする案**(ユーザー構想: トラックをカードとしてプレミックスに配置・アステリズムベルト・
何かのAPIでPixabay→語彙→MIDI・ネビュラ。Cubase上で他のプラグインと併用できるのでWeb Audioは不要になる)
- **最大の壁: VSTは自分が挿さったトラックの音(とMIDI)しか受け取れない**。他のトラックを読む・並べる・鳴らす仕組みはVST3に無い。
  「トラック=カード」は、各トラックに中継プラグインを挿して1つの本体の画面に集める形(iZotope Visual Mixer と同じ方式)。中継⇔本体の通信
  (共有メモリなど)は自前。Cubase自体の音量・ミュートを動かすなら MIDI Remote(JavaScriptのスクリプト)経由(音は扱えない)
- **ベルト**: トラックは流れ続ける音なので、(a) 各トラックはループで鳴らしたまま、ベルトの順に中継プラグインが開け閉めする(ゲート。
  Cubaseのテンポ・小節に同期できる)か、(b) 本体がサンプラーになって素材を順に鳴らす(カード=素材)。**最初に決めること: カードは
  トラック(流れ)か素材(鳴らせる音)か**
- **ネビュラの粒の効果**は、届くのが今の音の流れだけなので「直前の数秒を貯める」方式(リバースディレイ型など)に作り直し、感触が変わる。
  テープストップの追いつき方、レイテンシの申告、書き出しのたびに音が変わらないよう乱数の固定が要る
- **AI**: Gemini・PixabayはAPIキーだけで呼べるのでプラグインからも可。トラックの実際の音を「語彙」に聴かせられるのはWeb版より有利。
