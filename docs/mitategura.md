# 見立て蔵と Gmail 経由のデイリー

CLAUDE.md から移した機能別の経緯と決まり(2026-10-03 に分割)。その機能を触る時に読む。絶対条件・開発方針は CLAUDE.md。

## 見立て蔵(語彙帳、2026-10-02、`js/mitategura.js`)

ユーザー構想: 見立て蔵モデルの身振りは10種しかなく貧弱(鳥の声のような音・低音・ピロピロした反復)。日本の自然・風土の現象の数だけある
「語彙+小さなMIDIメロディ」を集めて、見立て蔵モデルを強くする。手動か、デイリータスク(11時の通知から選ぶ。下の節)で増やす。
- **集めるのは「部品」=知覚が切り替わる一瞬**(ユーザー「夜道でふと見上げると月光が輝いていた、石を割ったら瑪瑙だった、というその一瞬の音」
  「ストーリーや起承転結は見立て蔵モデルの生成物で、集めたいのはその部品」)。物の絵(鳥の声を旋律でなぞる等)ではない。最初の版の20件は写生の旋律で
  「かわいいメロディ群、ディズニー劇伴のよう」だったので作り直した。ものまね(ミッキーマウシング)は別のモデルの領分
- **音は和音階でなく「デチューン三層」**(ユーザーが渡した構造。「日本風土の無我の音は和音階でもなく、この雰囲気」): 1音を A=不動(そのまま)・
  B=+1・+2半音(ぶつかる。常に微小に揺れる)・C=+5セント(ほぼ同じ。常に微小に揺れる)で同時に鳴らす。サイン波のみ、エフェクトなし。
  揺れはB・Cの声ごとに非同期に3〜8秒に一度、±3セントへ1.8秒かけて移る。音量比 A .34 / B .14×2 / C .20、全体55%。**役割を混ぜない**
  (Aを揺らさない、BとCを同じ揺れにまとめない)。「和音なのか1つの音の揺れなのか判断しきれない」ことが狙い。`MU` と `scheduleMu()`(js/mitategura.js)
- **一瞬は三層の状態の変わり方で書く**: 層ごとに spread(Bの開き。0でAに重なる)・b・c(音量の倍率)・cdet(Cのずれの倍率)を持ち、morph のキーフレームで動かす。
  例: 霧が晴れる=BとCがAへ吸い込まれてただのサイン波に澄む(判断できない状態が識別へほどける)/雪解けの雫=澄んだ一滴から、広がる輪ほどBとCが増えてにじむ
- **響き「神秘」と「日常」**: 鳥・虫・波打ち際の「あえて神秘的でない音」(ユーザー要望)。最初は三層に音の滑り・速い断続・ノイズを足して鳴き声を合成したが、
  「印象ではなく、実際の音を電子合成した感じ」(ユーザー)=合成でのものまねになったので作り直した。今の考え方: 日常の部品も**聞いている時の時間の感じ**を音にする。
  引く=神秘さの正体の判断のつかなさ(Cのうなり・Bのぶつかり)を減らし、判断のつく澄んだ音へ。足す=時間の性格(反復・周期・密度・途切れ方)と三層の開閉。
  日常の6件: 軒先の雀(区切る)・夕方の鴉(横切る)・庭の蟋蟀(刻む)・真昼の油蝉(満ちる)・田の蛙(交わす)・波打ち際(寄せて返す)。窓の絞り込みに「響き」。
  滑り(bend)・断続(am)・ノイズ(noise)の仕組みは js/mitategura.js に残してあるが使っていない(ものまねの道具になりやすい)
  ユーザーの評価(2026-10-02): 神秘の7件は「まさにこれ」。日常の作り直し版は「まだ効果音寄りのものもあるけど、この方向性」。
  → 同日、雀(「ミッキーマウシングっぽい」)・鴉・蛙・波打ち際(「単純」)・蟋蟀(「ただの電子音」)は**消した**。日常に残るのは油蝉だけ
  **油蝉は残す**(ユーザー「なんか可能性を感じた。蝉の声を模しているけど蝉ではない、という異質感がホラーとかに使えそう」)。消したり「直したり」しない
- **デチューン三層を短いノートで散らすと効果音っぽくなるので避ける**(2026-10-02、ユーザー「霜柱を踏む と 線香花火 は傾向が一緒」)。
  一瞬は粒を散らさず、長めの音の三層の状態の変わり方で描く。霜柱 = 澄んだ高い一音のBが踏んだ瞬間に大きく開き、Cが激しくうなって砕け、狭い濁りへ潰れる。
  線香花火 = 火花を粒でなく、高い一音のCのずれ(うなりの速さ)とBのぶつかりで描き、ちらつきが遅く細くなってから玉が落ちる
- 神秘の部品は7件(Claudeが手で書いた): 夜道の月光(開く)・割れた石の瑪瑙(割れる)・霜柱を踏む(砕ける)・雪解けの雫(広がる)・霧が晴れる(晴れる)・
  梅の香が不意に(香る)・線香花火の最後の玉(落ちる)。時間は秒(1拍=1秒)。セントのずれは普通のMIDIの音符では表せないので、部品は音名+三層の状態で持ち、
  音はWeb Audioで鳴らす(Cubaseへ渡すならWAV)。窓のカードは切り替わり方の動詞・その一瞬の一言・ピアノロール(Aの音)・仕掛け。季節・感覚で絞り込み。
  確認: OfflineAudioContextで7件とも -10〜-16dB、霧が晴れるの振幅の揺れが晴れる前0.25→晴れた後1.00(うなりが消える)。**耳ではまだ**
- **生き物は「声の特徴・羽の色・佇まい」を総合して三層とうねりに落とし込む**(2026-10-02、ユーザー。試作 `birds-mockup.html`、git管理外。ユーザーの評価「とてもいい。このかんじ」):
  鳴き声のまね(合成)も録音もしない。声 = リズム・高さ・硬さ(Bの開き)、色 = 音域・明るさ・Cのうなりの速さ、佇まい = 時間の流れ方・動きと静止・パルス。
  6羽(カワセミ・キジ・ヤマドリ・ルリビタキ・オシドリ・トラツグミ)。うなりの速さはC層のずれ(Hz)そのもので決め、整数倍で重ねるとパルスになる(和文様の試作 `wamon-mockup.html` から)。
  **見立て蔵の音階はリディアン(D)だけ、デチューン三層構造を主体にする**(ユーザー「和音階よりリディアンのほうが自然っぽい」「選択肢が多すぎるのもあれなので、見立て蔵はリディアン」。
  試作のページには音階の切り替えがあるが、本体には付けない)。**箏は「いかにもなオリエンタリズム」になるので使わない。尺八は好評**。
  和文様(青海波・七宝・鱗・立涌・麻の葉・市松・紗綾形)も、リディアン+三層を「はじいた」抽象的なプラック(A が減衰、B は立ち上がりの一瞬だけぶつかる、C は余韻でうなる)で
  組み直した(試作 `wamon-pluck-mockup.html`)。**注意**: 5音の段で書いた形を「段×7/5の丸め」で7音へ写すと、F#とBが抜けて A C# D E G#(Aの琉球音階)になり、
  沖縄っぽく聞こえた(ユーザーの指摘で、鳴った音を数えて判明)。段はリディアンの7音の段として直接書く。
  **配色 → 音色の重なり**(ユーザー要望「プラック・琴・抽象音・その他の音色の重なり方に、羽や文様の配色を紐づけたい。色彩が飛び散る印象でいい」。試作 `irome-mockup.html`):
  色ごとに音色を1つ決める(藍 = 三層そのもの/水色 = ガラスのベル/朱 = 弦を強くはじく/橙 = 温かいプラック/緑 = 尺八/紫 = ずれた2本ののこぎり波/白 = 高い澄んだ点と息/
  黒 = 低くくぐもった影/金 = 金属/茶・赤銅 = くぐもった弦)。土台はいつも三層で、色の音色はその上に重なる。配色の面積の比がそのまま音色の比になり、
  「飛び散り」で配色の中の別の色が散り、強い音のまわりに他の色の粒が跳ねる。箏系の弦は朱・茶の色の一つとしてだけ使う。
- **文様7つと鳥6羽を見立て蔵に入れた**(2026-10-02、`js/mitatecolor.js`。試作 irome-mockup.html から移した): 窓の響きに「文様」「鳥」。カードは切り替わりの動詞・一言・
  配色の帯(実際に鳴る音の色の割合)・配色の譜面(時間×高さに色の粒。再生中は鳴る粒が光る)。音は safeOut を通し、残響つき。**飛び散りは 0.55 に固定**(窓に選択肢を増やさない)。
  `midiOf()` は飛び散りなしの配色どおりの音を、色ごとのパートで返す(1拍=1秒)。文様の季節は無季・感覚は視、鳥は季語の季節・聴と視。
  確認: ローカルのChrome(サインインなし)で21件が並び、文様・鳥・一瞬の部品が鳴って止まること、響きの絞り込み、エラーが無いことを確かめた。**耳ではまだ**
- ★と確認済み(実線の枠)は `state.prefs.mitate.ratings`(Drive)。未確認は点線
- **部品1つずつを .mid で書き出せる**(2026-10-02、ユーザー要望。カードの「⇩ MIDI」→ 書き出し先フォルダへ1トラック、`見立て_<名前>.mid`、テンポ60 = 1拍1秒)。
  セントのずれ・うなりは MIDI の音符では表せないので、入るのは音の高さ・長さ・強さだけ(一瞬の部品はAの音、文様・鳥は飛び散りなしの配色どおりの音)
- **LYRA Host で別の音源に鳴らす**(2026-10-02、ユーザー要望「尺八とかで鳴らしてみる」。LYRA Host は1トラックのまま): カードの「Host」→ `hostMidiOf()` の MIDI を
  `open`(cardId `mitate-<id>`、音源はホストに任せる、`preferSaved`+`restoreSound`)。**ノートで表せるのは A と B だけ**: B は +1・+2半音をその時の開き(spread)で
  半音に丸めた高さのノート(part「B」)で、b が 0.25 未満・丸めて0半音の間は鳴らさない(morph で B が閉じる・開く動きはノートの終わり・始まりに残る)。強さは A の 0.45〜0.75 倍。
  **C(+5セント)と±3セントの揺れは入らない**(ホストの MIDI の形にピッチベンドが無い)。文様・鳥は配色どおりの音のまま。Ctrl+L で送り返すとプレミックスのカードになる。
  三層を丸ごと再現する案は、Serum2 で A=Osc A・C=Osc B(Fine +5)・B=Osc C(ユニゾン2声)にし、morph と揺れをオートメーションで送る形(`Uni Detune` の値とセントの対応は未測定)
- **別の機能として作りたいもの**(ユーザー「ミッキーマウシングと壮大なオーケストラエンジンはまた別で作りたいね」): 見立て蔵には入れない。
  ミッキーマウシング(物の動きや鳴き声を音でなぞる)と、壮大なオーケストラの音のエンジン。配色の音のページは「これだけでBGM生成機として使えそう」とも

  (「安っぽい音でもちゃんととした管弦楽技法なら良い音楽になる。歴代のゲーム名曲がそう」)。ディヴィジ・楽器配置(席順)・主題の反復と展開(反復進行・断片化・反行・拡大・模倣・転調・保続音)・

  試作 `symphony-mockup.html`(git管理外): マス目かテキストで主題を描くと、4小節の主題で約1分(8小節で約75秒)の管弦楽に膨らむ。17楽器の合成のデモ音源、舞台の席順の図、区間ごとの技法の解説。

- **Gemini で語彙を足す(2026-10-02、`js/mitategen.js`)**: 見立て蔵の窓の「＋ Geminiで足す」→ 件数(既定10)・型(ランダム/1つ)・お題(おまかせ/今日の七十二候/自由)・
  **残す回数**(既定50。この端末で数えた今日の回数が「250 − 残す回数」に達したら止める)。
  - **型**(ユーザーの整理): **神秘型**(デチューン三層の状態の変わり方。音高は12音から自由=手書きの7件と同じ)/ **和文様型**(D リディアン+色ごとの音色。
    文様の形を音型の繰り返し・ずれ・噛み合いに、配色を音色の比に)/ **鳥型**(和文様型にデチューンを組み合わせ、声の特徴・羽の色・佇まいを総合。D リディアン)。
    生成のたびに型をランダムに選ぶ。**新しい型ができたら `TYPES`(js/mitategen.js)に1つ書く**(鳴らし方が新しければ js/mitategura.js の `hydrate()` も)
  - 1回の呼び出しで同じ型の2件を書かせ、もう1回で**反芻**(その一瞬らしいか・ものまね/劇伴/効果音になっていないか・帳と似ていないか。迷えば入れる)。落ちた・形が壊れたものは
    入れず、結果の窓に理由を出す。10件で約10回。呼び出しの間は4.5秒。プロンプトには「避けること」(ものまね・かわいい旋律・短い音の散らし・箏のオリエンタリズム・引用)と、
    帳の全語彙(似たものを避ける)と、型ごとのお手本(手書きの月光・霧が晴れる/七宝/ルリビタキをその型の形に書き直したもの)を入れる
  - アプリ側の整え方: 神秘型は短い音(0.35秒未満)が4つ以上・10秒超を捨てる。色の名前は日本語(萌黄→緑など)も読み、読めない色は捨てる。同じ名前の語彙は入れない
  - **保存**: Drive の LYRA フォルダの `lyra_mitategura.json`(`{ version, items: [{ id, type, createdAt, via, theme, review, data }] }`)。本体には `mitateFileId` だけ。
    自動保存が変わった時だけ本体より先に書く。読み込む前は書かない(空の帳で上書きしないように)。データは関数を持たない形で、文様・鳥は `LyraMitateColor.fromData()` が鳴らせる形に組み立てる
  - 窓のカードに「生成」の印と「外す」(ラベル付きの2択で確認。手書きの語彙には無い)。入った語彙は未確認(点線)
  - Gemini の1日の使用回数(目安): `js/gemini.js` の `geminiUsageToday()`。太平洋時間の日付ごとに、Google に届いた呼び出しを `localStorage` の `lyra.geminiUsage` で数える(別の端末・Apps Script の分は入らない)
  - 確認: Node で型ごとの整え方・10件で10回・反芻で落ちる・残す回数と1日の上限(429)で止まることを、ローカルの Chrome(Drive・Gemini を模擬)で窓からの流れ・帳のファイルの保存・
    生成した語彙の再生・「外す」を確かめた。**実機の Gemini での質・耳ではまだ**
  - **神秘型の身振りを割り当てる(2026-10-07)**: ユーザー指摘「神秘型が、ほとんど9割『ブゥーーン パァアアーン』といった低音に途中から高音が重なるデチューン三層構造で
    ワンパターン。最初に作らせた数種類のようなバリエーションがない」。お手本が月光・霧の2件(どちらも濁った持続音 → 澄む → 遅れて高い一点)で固定だったのが主な原因と見た
    (音の形の判定でも、手書き7件のうちこの形はこの2件だけ)。直したこと: (1) 身振り11種(`GESTURES`: 濁りが澄む/澄んだものが砕ける/一撃のあと縞/一点がにじむ/無音から浮かぶ/
    うなりの速さが変わる/高い所から沈む/ぶつかる二音が一つに/一つの音が呼吸する/不意に途切れる/薄い一点から満ちる)と音域4種を、1回の2件に重ならないよう割り当てる
    (「濁りが澄む」は選ばれにくく)。(2) お手本はその身振りの手書きの部品(無ければ月光・霧以外から)。(3) 帳の一覧の神秘の行に音の形(`shapeOf()`。「持続に遅れて高音」・音域・
    濁→澄)を添え、この形が帳の3割以上なら「今回は作らない」と書く。(4) 反芻で身振りどおりか・この形になっていないかを点検。生成した語彙の `data.gesture` に身振りの id が入る。
    Gmail 経由のデイリーのひな形は件数が決まっていないので、割り当てずに身振りの一覧から1件ごとに違うものを選ばせる(Apps Script の変更は要らない)。
    偏りの診断: 窓を一度開いた後のコンソールで `LyraMitateGen.shapeReport()`(神秘の部品ごとの形の表と、「持続に遅れて高音」の件数)。
    確認: Node で判定・割り当ての偏り(1000回で同じ身振り・音域の重なり0)・依頼の文・ひな形の差し込み口・反芻の文。**実機の Gemini で形がばらけるか・耳ではまだ**
- **見立て蔵モデルで語彙を使う(2026-10-02)**: 新しい生成器 **`mitate`(語彙)**(js/midi/generators.js)。Gemini は層ごとに目録(id・型・名前・切り替わり方・一言・季節・★・✓。
  ★1〜2は外す、確認済み・★4〜5を先に、最大90行)から `vocab` を選ぶだけで、呼び出しは今までどおり1回。見立て蔵モデルの生成器は `['mitate', 'gesture']`
  (合う語彙が無いモチーフは身振り)。帳に無い id・名前の層は身振りの層にする(黙って無音にしない)
  - 音: その語彙の ⇩ MIDI と同じ音(一瞬の部品は A の音、文様・鳥は配色どおりの音)を、秒 → 拍(テンポに合わせて、一瞬の時間の長さを保つ)に直して置く。現れ方は once(既定)/sparse/periodic/continuous。
    設計図の主音が D でなければ、語彙の音をまるごと主音へ移す(±6半音)。register があればオクターブで動かす
  - **設計図(`layer.vocabNotes`)に音の写しを入れる**ので、帳から外した後も、振り直し・伸ばすで鳴る。作り直しで Gemini に返す形には写しを入れない

## Geminiの残りの枠を使う日次の仕事(2026-10-02 に見立て蔵の語彙集めで実装。下は構想の時の整理と、実装の決まり)

- **実装(2026-10-02)**: `gas/Code.gs`(Apps Script)・`gas/Page.html`(開始のページ)・`js/dailyjobs.js`(LYRA 側)。設置は README.md 手順10
  - **依頼** `lyra_daily_request.json`: LYRA が自動保存のたびに、変わった時だけ書く(帳を読む前は書かない)。中身はモデル名・1日の上限・結果ファイルの id・
    この端末の今日の使用回数・取り込み済みの回・見立て蔵の仕事(`LyraMitateGen.templates()` = 型ごとのプロンプトのひな形とスキーマ、お題の行、帳の一覧、七十二候の表)。
    **プロンプトの正本は LYRA(js/mitategen.js)**。Apps Script は `{{COUNT}}`・`{{THEME_LINE}}`・`{{BOOK}}`・`{{N}}`・`{{ITEMS}}` を差し込んで呼ぶだけ
  - **結果** `lyra_daily_result.json`: LYRA は最初に空で作るだけで、以後は書かない。Apps Script が `runs`(最大20回)と自分の使用回数 `usage` を書く。
    1組(2件+反芻)ごとに途中経過を書く。Gemini の出力はそのまま置き、**形を整えるのは LYRA の取り込み**(`toRecord`)
  - Apps Script の決まり: 1日1回まで(日本時間の日付。`LAST_RUN_DAY`)、開始の時点で残りが「残す回数」以下なら始めない、1組ごとに残す回数と止めるボタンを見る、
    1日の上限(429)と API キーが無い時はその場で止める、4.5分を超えたら1分後の時刻トリガーで続きを動かす(6分の制限)、503/500 は待って再試行、
    壊れた JSON は1回だけやり直す。その回に足した語彙は、次の組の帳の一覧に足す(同じ回の中で似たものを避けるため)
  - 「今日の残り」= 上限 − LYRA の端末で数えた分(依頼に書いたもの)− Apps Script で数えた分。LYRA の窓・「残す回数」も Apps Script の分を足して数える(`window.geminiRemoteUsage`)
  - 取り込み: LYRA を開いた時(帳を読んだ後)、取り込んでいない回があれば「今はしない/帳に取り込む」を聞く。見立て蔵の窓にも「デイリーの結果を取り込む」。
    取り込んだ回の id は `state.prefs.mitate.importedRuns`(依頼に写すので、メールの「未取り込み」からも消える)
  - 確認: Node で、LYRA の本物の依頼を Apps Script のコード(Drive・Gemini・プロパティなどを模擬)に読ませ、メール・10件の実行・1日1回・429・残す回数・
    6分の制限での続き・LYRA の取り込み(今はしない → 取り込む)・使用回数の合算を確かめた。**本物の Apps Script での設置と実行はまだ**
